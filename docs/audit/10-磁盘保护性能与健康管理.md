# 10 · 磁盘保护、性能与健康管理（Phase 1 + Phase 2）

- 日期：2026-11-12
- 版本：v1.0.0（未改版本号）
- 状态：Phase 1（磁盘画像/I-O 模式/健康摘要）与 Phase 2（快速检查）已落地；Phase 3 为后续方案。

---

## 一、本轮落地内容

### 1. 磁盘画像

新增 `diskprofile.go`：

- `GetDiskProfiles()` 返回：
  - 逻辑盘：盘符、卷标、容量、剩余、是否 NTFS、是否 SSD；
  - 物理盘：型号、SSD/HDD/SCM、总线（NVMe/SATA/USB/RAID）、健康状态、运行状态、容量、转速、SMR 提示；
  - 当前 I/O 模式。
- 数据源优先 `root\Microsoft\Windows\Storage` 的 `MSFT_PhysicalDisk`；失败回退 `Win32_DiskDrive`，读不到写 `Unknown`，不编数据。
- SMR 仅做型号关键词提示，标注 `likely/unknown`，不作为结论。

### 2. I/O 模式

新增 `diskio.go`：

| 模式 | 目录 worker | item 并发 | 删除并发 | 适用 |
|---|---|---|---|---|
| 静音 quiet | 2 | 2 | 2 | 机械盘、笔记本、夜间 |
| 均衡 balanced | CPU 4–8 | 2–6 | 8 | 默认 |
| 极速 fast | CPU×2（≤16） | ≤12 | 12 | NVMe/台式机 |

- 模式持久化到 `%LOCALAPPDATA%\ahtool\diskio.txt`。
- 前端磁盘页新增「磁盘 I/O 模式」切换条；Wails 绑定 `GetDiskIOMode` / `SetDiskIOMode`。
- `scanWorkers()`、`ScanAll`、删除阶段已改为读当前模式，不再只看 CPU 核数。

### 3. 机械盘降并发

- `deepJunkScanWorkers(ctx, root, workers)`（`junk_scan.go:76`）支持指定 worker。
- `deepJunkScanDrives` 对每个盘先判断 `diskIsSSDByDrive`：机械盘即使处于极速模式也最多 2 路，避免多 worker 随机读造成明显寻道声/卡顿（`junk_scan.go:185-191`）。
- 目录读取闸门容量改为 32 的上限，实际并发由模式/worker 数控制。

### 4. SSD 感知的碎片整理

- `disk-defrag-optimize` 改为 `Run`：
  - SSD：日志明确“只执行 TRIM / retrim，不移动文件数据”；
  - HDD：提示“会移动数据，建议空闲/接通电源时进行”；
  - 仍调用 `defrag <盘符> /O`，不改变原功能。

### 5. 前端健康摘要

`design/disk.js` + `design/disk.css`：

- 磁盘页顶部新增 I/O 模式切换；
- 新增「物理磁盘健康」卡片：型号、SSD/HDD、总线、健康色（Healthy/Warning/Unhealthy/Unknown）、容量、转速、SMR 提示；
- 盘符卡片显示 SSD/HDD 标签；
- 磁盘页加载时调用 `GetDiskProfiles`，失败静默，不影响原有空间分析。

## 二、当前优点

- 不再用一套并发打所有盘：机械盘默认低并发，SSD 可提速。
- 用户可在“静音/均衡/极速”之间选择，保护与性能不再二选一。
- 磁盘页能看到物理盘健康/SMR 提示，不再只有“已用/剩余”。
- SSD 碎片整理有明确提示，避免用户误以为 SSD 需要传统整理。
- 读不到健康信息时显示 Unknown，不伪造。

## 三、当前限制

- I/O 模式是**全局**的，还不是“每块盘单独配置”；多盘同时扫描时取全局模式，机械盘另有 2 路上限。
- SMR 仅型号启发式，覆盖不全；不能替代厂商工具。
- 健康信息来自 WMI，NVMe 原始 SMART/温度/磨损尚未接入。
- 还没有磁盘检查报告、chkdsk 计划修复、TRIM 一键、分区只读视图、健康历史趋势。
- 静音模式降低并发，扫描会变慢；这是有意取舍。

## 四、Windows 本地验证步骤

1. 构建并启动 `ahtool_v1.0.0.exe`，进入「磁盘空间」页。
2. 顶部应出现「磁盘 I/O 模式」：静音/均衡/极速；点击切换应 toast，并写入 `%LOCALAPPDATA%\ahtool\diskio.txt`。
3. 应出现「物理磁盘健康」卡片：
   - C 盘 SSD 显示 SSD；
   - D 盘 HDD 显示 HDD，若型号命中 SMR 关键词会提示；
   - 健康状态来自 `MSFT_PhysicalDisk`，读不到显示“未知”。
4. 选择「静音」后跑一次垃圾扫描/深度清理，观察 HDD 寻道声与卡顿是否下降（主观指标），扫描耗时会上升。
5. 工具库 → 磁盘优化整理：
   - 选 C（SSD）应提示“只执行 TRIM / retrim”；
   - 选 D（HDD）应提示“会移动数据，建议空闲时进行”。

若健康卡片为空：先看是否以管理员运行；再在 PowerShell 执行：

```powershell
Get-PhysicalDisk | Format-List FriendlyName,MediaType,BusType,HealthStatus,OperationalStatus,Size,SpindleSpeed
```

## 五、Phase 2 已落地：磁盘快速检查

新增 `diskcheck.go` + 磁盘页“快速检查”按钮：

- 物理盘健康（MSFT_PhysicalDisk / Win32_DiskDrive 回退）；
- 卷剩余空间（<10% 注意，<5% 异常）；
- NTFS dirty 标志（`fsutil dirty query`，只读）；
- System 日志里 `disk/Ntfs/volmgr/volsnap` 的 Error/Warning（`wevtutil qe`，只读，最近 10 条）；
- 报告写入 `%LOCALAPPDATA%\ahtool\reports\diskcheck_<盘符>_<时间>.txt`；
- 不运行 `chkdsk /f`、不修复、不删除；深度扫描引导到工具库的 `chkdsk /scan`。

### Phase 3 已落地（本轮）

- 健康历史：每次快速检查追加到 `%LOCALAPPDATA%\ahtool\diskhealth\history.json`，最多 200 条；检查弹窗显示最近 5 次。
- 卷信息：报告内显示文件系统、卷标、分区号、BitLocker 状态（读不到写 Unknown）。
- 删除清单：`SpaceDelete` 把本次删除的路径/原大小/原修改时间/成功失败写到 `%LOCALAPPDATA%\ahtool\reports\delete_<时间>.json`。
- TRIM 一键：SSD 选中时磁盘页出现「TRIM」按钮，二次确认后执行 `defrag <盘符> /O`；非 SSD 直接拒绝。
- 卷/分区只读视图：磁盘页「卷信息」按钮，展示盘符、文件系统、卷标、容量/已用、健康、磁盘/分区号、BitLocker。
- 修复 WMI 数值属性读取：`wmi.go` 不再用 `VARIANT.ToString()`（只支持 BSTR），改用 `Value()` 兜底；`MSFT_PhysicalDisk` 的 MediaType/BusType/HealthStatus 不再显示 Unknown。
- 碎片分析入口：选中机械盘时显示「分析碎片」按钮，执行只读 `defrag /A`，结果以弹窗展示。

### 后续待做

- 计划 `chkdsk /f`（强确认、重启生效）。
- 每盘独立 I/O 策略与全局重活锁（垃圾清理/查重/整理/DISM 互斥）。
- 可选隔离区（删除前移动高风险文件）。
- HDD 碎片分析/整理入口与空闲检测。
- 分区表/卷的完整只读视图与健康趋势图。

### 保护红线

- 系统盘/引导区/恢复分区只读；
- SSD 不做传统碎片整理；
- 永久删除保留二次确认与清单；
- 不实现格式化/分区/改盘符/缩容等破坏性操作。
