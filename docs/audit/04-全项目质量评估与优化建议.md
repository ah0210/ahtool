# 04 · 全项目质量评估与优化建议

- 对象：`ahtool` v1.0.0（原 `3z9wOpt` v1.1.0）
- 日期：2026-11-12

## 二、安全与正确性问题（按严重度）

> 详细证据与修复建议见 [01](01-安全性与真实性评估报告.md)。这里只列对“质量”影响最大的项。

### P0

1. **`SpaceDelete` 任意路径永久删除**（`space.go:510`）：**第二轮已修** —— 只允许本次 MFT 索引中解析为文件的路径（`mftscan.go:461`），拒绝重解析点/运行时保护路径，删除只走单文件；`os.RemoveAll` 已移除。剩余：TOCTOU 需句柄/FRN 删除才能彻底消除。
2. **强制清理的删除面**（`appclean.go:1605`）：**第二轮已修** —— 注册表整树删前 `reg export`，命中系统保护区/共用容器键直接跳过；目录仍走 `resDirSafe`/运行时保护。剩余：同厂商关键词匹配仍建议收紧。
3. **优化项无原值备份**（`optimize.go:304-409`）：**第二轮部分修复** —— `safe-3` 还原不再关闭 UAC，`ForegroundLockTimeout` 还原改为系统默认 200000；但仍是固定常量，不是用户原值。建议下一轮：写入前记录原值，还原写回原值；安全项默认不勾。

### P1

4. **驱动强删**（`drivers.go:730`）：**第二轮已修** —— 删除前 `pnputil /enum-devices /drivers` 检查占用，命中即拒绝。
5. **更新链路**（原版）：清单无签名；`ApplyUpdate` 不重验哈希（`update.go:661`）。本分支默认关闭，恢复前需补签名。
6. **`winold` / `SpaceOpen` 的 cmd 字符串拼接**（`junk_clean.go:908`、`space.go`）：建议原生 API/参数化。
7. **`netNicRestart` 中文硬编码**（`tools_net.go:548`）：**第二轮已修** —— 兼容英文 `Enabled`，接口名取第 4 列起。

## 四、Bug 与可维护性问题

1. **`optimize_data.go` 生成器缺失**：文件头写“Code generated by `_proto/gen_optimize_data.py`”，但仓库没有该脚本/XML；154 项无法复现生成。建议：补生成器或将文件标记为手工维护并加校验测试。
2. **`service.go` 原版的“官方指纹/服务大厅”与 README 不一致**：本分支已重写，但历史文档里仍有旧描述（已归档）。
3. **`frontend/dist` 的定位**：原版 `build_frontend.js` 已失效；本分支已归档该脚本，`frontend/dist` 仅作 `go:embed` 占位。建议在 README 写清（已写）。
4. **测试可运行性**：大量测试需要管理员/真实磁盘/服务/注册表；本分支已给 23 个文件加 `//go:build manual`，但仍有测试会写 `%LOCALAPPDATA%`（`optimize_test.go` 的 HKCU 测试键、`oplog_test.go` 用 t.TempDir 等）。建议进一步隔离。
5. **`toolkit_test.go` 数量断言**：36 个工具 + `12+9+4+5+6` 分布钉死；增删工具必须同步。属有意设计，但需在开发文档强调（已写）。
6. **`service_test.go` 原契约**：原测试断言必须有官网/微信/QQ 链接；本分支已重写为“不得有外链”，避免旧契约阻碍解绑。
7. **`update_test.go`**：仍保留完整更新逻辑测试（通过 `updateManifestURLOverride` 注入），本分支默认停用不影响测试。
8. **`netNicRestart` 中文解析**：**已修**（兼容英文，接口名取第 4 列起）。
9. **`GetInstalledUpdates` 排序**：`parseWmiDate` 失败时 `t` 为零值，排序会把它排到最后；可接受但应显示“日期未知”。
10. **`fullMD5` 错误处理**、**`dupBest` 计数**（见性能表）。
11. **`StopTool` 孙进程**：未使用 Job Object，取消后可能残留子进程。
12. **错误吞掉**：`walkSize`、`recycleMeasure`、部分注册表扫描忽略错误；UI 可能显示 0 而不是“读取失败”。建议区分“0”与“未知”。
13. **`gofmt`/行尾**：本轮已统一为 LF 并 `gofmt -w`（`gofmt -l` 为 0）；建议补 `.gitattributes`（`*.go text eol=lf`）防止回归。工作量 S。

## 六、结论

- 代码可编译、可测试编译、静态检查干净；工程基础**具备二次开发条件**。
- 最大的质量债不是“能不能跑”，而是**删除与回滚的安全边界**：`SpaceDelete`、强制清理、优化还原。建议二次开发第一周先处理这三项。
- Defender 误报主因是“无签名 + 高危行为组合”，不是代码混淆或恶意逻辑；签名与行为收敛比改代码风格更有效（见 02）。
