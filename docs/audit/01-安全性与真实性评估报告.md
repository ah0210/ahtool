# 01 · 安全性与真实性评估报告

- 审计对象：`ahtool` v1.0.0（基于原项目「无名大叔系统优化工具箱」/ `3z9wOpt` v1.1.0 的未改动原始副本）
- 审计日期：2026-11-12
- 审计方式：**只读静态审计** + 交叉编译 / `go vet` / 测试编译 + 前端 `node --check`；未在 Windows 上运行 exe，未执行任何清理、优化、服务启停、注册表写入、驱动或更新操作。
- 结论等级：
  - 功能真实性：**基本真实**（宣称的模块与数据大多有实现；少数为占位/估算）。
  - 数据真实性：**总体真实**（硬件/磁盘/蓝屏为真采集；健康分、耗时、部分“可清理量”为估算或提权后可删量）。
  - 宣传真实性：**原版存在明显不符**（“不联网、不收集任何数据”与在线更新/测速/公网 IP 查询矛盾）；本分支已改写文案。
  - 安全性：**高风险工具类软件的正常形态，但存在若干必须正视的权限与删除面**。本分支已修掉其中一部分（标注“已修”）。

> 未覆盖项：Windows 真机行为、Defender 实际拦截、驱动/服务/注册表真实写入结果、WebView2 渲染、UAC 提权链、多引擎扫描。所有“推断”均已标注。

## 一、三层真实性结论

### 1. 功能真实性（宣称能力是否有代码在跑）

| 宣称 | 代码证据 | 结论 |
|---|---|---|
| 10 个功能模块 | `main.go` 页面路由 + `design/` 12 个独立模块 | 真实 |
| 36 个系统原生工具 | `tools_*.go` 共 36 条 `regTool`；`toolkit_test.go:19` 钉死 36 | 真实 |
| 154 项注册表优化 | `optimize_data.go` 151 条 + `optimize_extra.go` 3 条 | 真实 |
| 9 组 93 项垃圾清理 | `junk_items.go:187` 起，`grep -c 'ID:'` = 93 | 真实 |
| MFT 直读 NTFS | `mftscan.go:86` `FSCTL_GET_NTFS_VOLUME_DATA` + `DeviceIoControl` | 真实 |
| CPUID / SMBIOS / WMI / DXGI | `hwspec_amd64.s`、`hwspec.go`、`wmi.go` | 真实 |
| 蓝屏转储解析 | `bsod.go` 手工解析 DUMP_HEADER64，测试构造样本 | 真实 |
| 在线更新 / 官方指纹 | `update.go` 完整实现 | 真实存在；本分支默认停用 |
| 服务大厅 / 远程服务 | 原 `service.go` 硬编码服务卡片、微信、QQ、赞赏 | 真实存在；本分支已移除 |

### 2. 数据真实性（数字是不是真采集、口径对不对）

- **硬件信息**：WMI / SMBIOS / CPUID / DXGI 真读，读不到写“读不到”，未发现硬编码假数据。`hwspec.go:241` 在 CPUID 0x0B 缺失时用“核数=线程数”兜底，属**推断值**，老 CPU 可能把逻辑核数当物理核数。
- **磁盘空间**：`mftscan.go` 真读 MFT；`space.go` 的重复文件按全量 MD5（`fullMD5`），但读错误时会返回已读部分的哈希（`space.go:467` 附近），存在把不同文件判成同一份的风险（见 04）。
- **垃圾“可清理量”**：扫描期用 `probeCanDelete`（`junk_priv.go:193`）以管理员 + `SeBackup/SeRestore` 权限试开，代表“**提权后**能不能删”，不是普通用户口径；`WinSxS\Temp` 等 ACL 受保护文件会因特权而进入统计。README 未说明这一点。
- **健康分 / 耗时 / 测速**：健康分由五项结果加权（`design/ui-prototype.html` 内计算），是**产品化评分**，不是微软或行业标准；耗时为实测 `time.Since`；测速是真实 HTTP 并发，但 48 线程、600MB 上限会受节点限速影响。
- **“预计节省”类文案**：前端存在固定文案（如“约 20 秒”“3 分钟”），属估算，不应理解为承诺。

### 3. 宣传真实性（README 与代码对照）

原 README 首屏写“**不联网、不收集任何数据**”，与以下代码矛盾：

| 行为 | 位置 | 触发 | 发送内容 |
|---|---|---|---|
| 启动静默检查更新（原版） | `design/ui-prototype.html` 原 `setTimeout(checkUpdate(true), 3500)`；`update.go:46` 原清单地址 | 启动 3.5 秒后 | 版本号、UA、IP（HTTP 层可见） |
| 手动检查更新 / 下载 | `update.go:304` / `530` | 用户点击 | 同上 + 下载包 |
| 官方指纹校验 | `update.go:465` | 用户点击 | 本机 exe SHA256 与服务端比对 |
| 宽带测速 | `speedtest.go:44-53` | 用户点击 | 访问微信 CDN、华为云、360、网易镜像、Cloudflare、Ookla；上传 1MB 随机数据 |
| 公网 IP 归属地（原版） | `speedtest.go` 原 `http://ip-api.com/...` | 测速结束 | 出口 IP、地区、运营商（**明文 HTTP**） |
| 局域网信息 | `toolkit.go:233` | 打开局域网面板 | UDP dial `223.5.5.5:53`（不实际发包，仅取出口网卡地址） |

本分支处理：
- 在线更新与指纹校验默认关闭（`update.go:49-55`），启动不再调用 `checkUpdate`；
- 移除全部官网/社群/赞赏/远程服务外链（`service.go` 已重写）；
- 停用明文公网 IP 查询（`speedtest.go:527-534`）；
- README 改为如实说明“默认不联网，唯一按需联网是测速”。

## 二、安全发现（按严重度）

> 说明：以下“已修”指本分支已经落地的改动；“遗留”指仍存在、建议后续处理。

### S0 · 任意路径 / 任意递归删除面（第二轮复核后大部分已修）

1. **`FreeCleanApp` 目录删除**：`appclean.go:1605` 起，原版对 `sess.dirs` 直接 `removeTreeSizedCtx`，不经过 `resDirSafe` / 运行时保护。`sess.dirs` 来自注册表 `InstallLocation` 与关键词扫描；`HKCU\...\Uninstall` 普通用户可写，伪造 `InstallLocation=C:\Windows` 后，管理员点“强制清理”即可递归删系统目录。
   - **已修**：删除前增加 `resDirSafe`、`isProtectedRuntimePath`、`isReparsePoint` 三道闸（`appclean.go:1656-1669`）；残留清理同样加闸（`appclean.go:1559-1570`）。
   - **已修（第二轮复核）**：`sess.regKeys` 整树删除前先 `reg export` 备份；命中系统保护区或共用容器键（MuiCache / Run）直接跳过（`appclean.go:1644-1663`）。
   - **遗留**：同厂商关键词匹配仍可能过宽，建议后续收紧或改为人工勾选。

2. **磁盘空间页 `SpaceDelete`**：`space.go:510` 接受前端传入的任意路径，只做 `assessPath`；`space_safety.go` 的一级目录保护实际只挡盘符根/空路径，`C:\Users`、`D:\Data` 可整树删除。删除为永久删除（`SHFileOperation` 不带 `FOF_ALLOWUNDO` + `os.RemoveAll` 兜底，`space.go:539-560`）。
   - **已修（第二轮复核）**：`SpaceDelete` 现在要求路径必须在**本次 MFT 扫描索引**中解析为文件（`mftscan.go:461` `nodeByPath`），并拒绝重解析点、运行时保护路径；删除只允许单文件，`os.RemoveAll` 已移除（`space.go:510-568, 570-600`）。UI 仍保留二次确认。
   - **遗留**：TOCTOU 无法完全消除（检查与删除之间路径仍可能被替换），建议后续用文件句柄/FRN 删除。

3. **`deepjunk` 全盘清理**：原版 `junk_clean.go:1038` 直接 `os.Remove`，不像目录型清理那样检查运行时保护。
   - **已修**：新增 `isProtectedRuntimePath` + `isReparsePoint` 拦截（`junk_clean.go:1042`）。
   - **遗留**：仍可能在用户文档目录删除 `.tmp/.log/.bak/.old/.dmp`；建议默认只清系统缓存目录，把“全盘零散垃圾”改为显式二次确认。

4. **重解析点目标删除**：原版 `removeNow` / `probeCanDelete` 的 `CreateFile` 未带 `FILE_FLAG_OPEN_REPARSE_POINT`，符号链接会被跟随，删除的是目标。
   - **已修**：`junk_priv.go:157`、`:203` 已加该标志。

### S1 · 提权与权限面

- `app.manifest:9` 要求 `requireAdministrator`，启动即 UAC 提权。
- `junk_priv.go:83-122` 主动启用 `SeBackupPrivilege` + `SeRestorePrivilege`，删除可绕过目标 ACL；扫描期使用同一特权，因此“可清理量”是提权后口径。
- 本分支未改变提权模型；建议在 README/首次启动中明确说明，并提供“只读模式”或按功能降权启动（工作量大）。
- **命令构造**：
  - 原版 `appclean.go` 卸载命令解析失败时回落 `cmd.exe /c <注册表原串>`（`buildUninstallCmd`），构成低权用户写 HKCU 卸载项 → 管理员执行任意命令的通道。
  - **已修**：只接受绝对路径或 System32 内真实系统程序；MSI 无 ProductCode 直接拒绝；不再走 `cmd /c`（`appclean.go:1296-1320`）。
  - **已修（第二轮复核）**：`winold` 改为参数化 `takeown` / `icacls` + Go 删除链（`junk_clean.go:906-914`）；`SpaceOpen` 去掉 `cmd /c start` 兜底，只走 `explorer /select`（`space.go:720-729`）。
- **裸命令名**：原版 `appclean_uwp.go`、`junk_reg.go` 用裸 `powershell`；本分支已改为 `resolveSystemExe("powershell.exe")`。`tools_net.go:253/263/332` 仍以 `resolveExe("powershell.exe")` + `-ExecutionPolicy Bypass` 执行隐藏 PowerShell，属行为特征风险（见 02），但不是 PATH 劫持。

### S1 · 注册表批量写删

- `optimize.go:304-409` 直接写 HKLM/HKCU，改服务启动类型，执行 `cmd.exe /c`；**仍没有全量原值快照/自动还原点**，`Restore` 仍是源数据里的固定常量。
- **已修（第二轮复核）**：`ForegroundLockTimeout` 还原值从 100 改为 Windows 默认 200000（`optimize_data.go:83`）；`safe-3` 的还原不再把 `EnableLUA` 写成 0（`optimize_data.go:866-869`）。
- **遗留**：仍未实现“写入前记录原值、还原写回原值”；这是下一轮最大的一项。
- `junk_reg.go:512` 整树删注册表键，原版在“读不到键”时一律当“已删除”返回成功；本分支已区分 `ERROR_FILE_NOT_FOUND` / `ERROR_PATH_NOT_FOUND` 与拒绝访问（`junk_reg.go:530`），但仍没有删除前导出备份。
- 建议：所有注册表写入前导出 `.reg` 或记录原值；还原动作改为“写回原值”而不是固定默认值；把 `safe-3` 等会降低安全性的还原动作单独标红。

### S2 · 系统级破坏性操作

- 删还原点：`junk_clean.go:916` `vssadmin delete shadows /all /quiet`。
- 清 Defender 隔离区/历史：`junk_items.go:276-280`、`junk_clean.go:417-448`。
- 截断事件日志：`junk_clean.go:937` `wevtutil cl Security` 等。
- DISM 组件清理 `/resetbase`：`junk_clean.go:950`，清完旧更新无法卸载。
- 重建更新缓存：`junk_clean.go` `wucachedeep` 停 `wuauserv/cryptSvc/bits/msiserver` 后 `defer` 恢复；进程被强杀时服务可能停在停止状态。
- `MoveFileEx(MOVEFILE_DELAY_UNTIL_REBOOT)`：`junk_rebootdel.go:84`，写入系统重启删除队列，无 UI 撤销。
- 驱动删除 `/force`：`drivers.go:730-737` `pnputil /delete-driver <oem> /uninstall /force`；**已修（第二轮复核）**：删除前先用 `pnputil /enum-devices /drivers` 检查是否有设备正在使用，命中即拒绝。
- 这些功能本身是该类工具的卖点，但应在 UI 上逐项确认、默认关闭、并提供还原/备份；本分支未删除功能（遵守“不偷偷删功能”的底线）。

### S2 · 更新链路信任模型（原版）

- 清单 HTTPS（`update.go:304`），下载强制 HTTPS（`update.go:530` 起）并校验 SHA256（`update.go:635` 起）；但清单本身无签名，服务器被控即可下发任意包。
- `ApplyUpdate` 只检查文件大小，不重新校验哈希（`update.go:661-680`）；真正替换由复制自身作为更新器完成（`update.go:723-782`），无 Authenticode 校验。
- 本分支默认关闭；若二次开发恢复，建议清单签名 + 代码签名 + 更新器独立签名校验。

### S3 · 隐私与本地数据

- `oplog.go:37` 在 `%LOCALAPPDATA%\ahtool\oplog.json` 记录优化/启动项/工具操作，最多 300 条，不上传；内容可能含软件名、路径、参数，属个人使用痕迹。
- `startup_state.json`（`startup.go:99`）、`pending_reboot.json`（`optimize_reboot.go`）、`iconcache`、`reports` 均在 `%LOCALAPPDATA%\ahtool`。
- 诊断报告（`service.go:179`）只在本机生成，本分支已移除联系方式与上传。
- 垃圾清理会清浏览器缓存/Cookies/使用痕迹（默认不勾痕迹类），属用户主动选择。
