## 二、实际执行的命令

```bash
# 1. 工具链（本机只有 Go 1.22.8；go.mod 要求 1.26.0）
curl -sSL -o go.tgz https://mirrors.aliyun.com/golang/go1.26.0.linux-amd64.tar.gz
tar -xzf go.tgz   # → /mnt/tos/workspace/toolchain126/go

# 2. 依赖（proxy.golang.org 超时，改用镜像）
export PATH=/mnt/tos/workspace/toolchain126/go/bin:$PATH
export GOTOOLCHAIN=local GOPROXY=https://goproxy.cn,direct
go mod download

# 3. 静态检查 + 测试编译
go vet ./...
go test -c -o /tmp/ahtool.test.exe .

# 4. 重建版本资源
go-winres simply --arch amd64 --out rsrc --no-suffix --manifest gui --admin \
  --icon app.ico --file-version 1.0.0.0 --product-version 1.0.0.0 \
  --file-description "ah系统优化工具箱" --product-name "ah系统优化工具箱 (ahtool)" \
  --original-filename "ahtool.exe" --copyright "GPLv3"
mv rsrc_windows_amd64.syso rsrc.syso   # --no-suffix 未生效时的兜底

# 5. 交叉编译
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -tags desktop,production \
  -ldflags "-s -w -H windowsgui -X main.appVersion=1.0.0 -X main.buildDate=2026-11-12" \
  -o bin/ahtool_v1.0.0.exe .

# 6. 产物核验
file bin/ahtool_v1.0.0.exe
go version -m bin/ahtool_v1.0.0.exe
sha256sum bin/ahtool_v1.0.0.exe
go-winres extract bin/ahtool_v1.0.0.exe
```

### 环境与踩坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `go: downloading go1.26.0 ... proxy.golang.org: i/o timeout` | 本机 Go 1.22.8 自动切工具链，`proxy.golang.org` 不可达 | 下载独立 Go 1.26.0，`GOTOOLCHAIN=local` |
| `golang.org/x/sys@v0.48.0 requires go >= 1.26.0` | 依赖硬性要求 | 必须用 Go 1.26；不能降到 1.24/1.25 |
| `go mod download` 卡住 | 默认 GOPROXY 不可达 | `GOPROXY=https://goproxy.cn,direct` |
| `tar -xzf` 在 `/mnt/tos` 上很慢 | 网络文件系统 | 等待完成；未影响最终构建 |
| `package unsafe is not in std` | 在 tar 解压未完成时就开始编译 | 等 `go/src/unsafe` 出现后再构建 |
| `--no-suffix` 仍生成 `rsrc_windows_amd64.syso` | go-winres 版本行为 | 重命名为 `rsrc.syso` |

## 三、Win11 双击无反应的根因与修复

上一版 exe 在 Win11 双击无反应，已定位到代码级原因：

- Wails v2 `assetserver.NewAssetHandler` 启动时要求 `go:embed` 资产 FS 中存在 `index.html`；
- 缺失时 `wails.Run` 返回 `no \`index.html\` could be found in your Assets fs.FS`；
- 程序以 `-H windowsgui` 编译，没有控制台，`log.Fatal(err)` 的输出不可见 → 表现为“双击无反应”。

原项目把 `frontend/dist/index.html` 放在 `.gitignore` 里，由已失效的 `build_frontend.js`
生成；上一轮清理没有保留这个占位文件。现已：

- 新增 `frontend/dist/index.html` 占位（实际页面仍由 `serveDesignPage` 中间件返回）；
- 启动前检查 embed 里是否有 index.html，缺失时弹 MessageBox；
- `wails.Run` 失败时弹 MessageBox 并写 `%LOCALAPPDATA%\ahtool\startup.log`；
- 新增 `-diag` 参数输出 WebView2/权限/路径报告。

## 四、怎么在 Windows 上验证

1. **哈希**：

```powershell
Get-FileHash .\ahtool_v1.0.0.exe -Algorithm SHA256
# 应为 dcfd8159dab0d041dc278974c3ce067ccee45d71551e1684ec360870a5e30af6
```

2. **版本资源**：

```powershell
(Get-Item .\ahtool_v1.0.0.exe).VersionInfo | Format-List *
# FileVersion / ProductVersion 应为 1.0.0.0
# ProductName 应为 ah系统优化工具箱 (ahtool)
```

3. **双击启动**：
   - 应弹出 UAC（`requireAdministrator`）；
   - 窗口标题应为「ah系统优化工具箱 v1.0.0」；
   - 侧栏版本应显示 v1.0.0；设置 → 关于应显示版本、构建日期、GPL-3.0、当前 exe SHA256；
   - 帮助与诊断页应能生成报告（纯本机）。

4. **只读自检**（不弹 GUI，建议在 VM 中）：

```powershell
.\ahtool_v1.0.0.exe -diag
.\ahtool_v1.0.0.exe -cli -nofull
```

5. **若启动失败**：
   - 先运行 `.htool_v1.0.0.exe -diag`，看弹窗与 `%TEMP%\ahtool_diag.txt`；
   - 看 `%LOCALAPPDATA%\ahtool\startup.log`（`wails.Run` 错误会写这里）；
   - 右键 exe → 属性 → 勾选「解除锁定」（Mark-of-the-Web）；
   - 检查 Windows 安全中心 → 保护历史记录 / Smart App Control 是否拦截；
   - 检查是否缺 WebView2 Runtime（Win10/11 通常自带；LTSC 可能需安装）；
   - 查看事件查看器 → Windows 日志 → 应用程序。

> 本环境没有 Windows/Wine，**未实际双击运行**；以上是验证步骤，不是已验证结果。

## 五、可复现构建（CI / 其他机器）

本包已验证：从交付包内源码用同一 Go 1.26.0 + `-buildvcs=false -trimpath` 重建，
exe SHA256 与包内预构建 exe 完全一致（`f750b1bb...`）。构建脚本已统一加
`-buildvcs=false`，避免把本机 git 信息写进二进制。

最小 workflow（已放在 `.github/workflows/build.yml`）：

```yaml
- uses: actions/setup-go@v5
  with: { go-version: '1.26.x' }
- run: go build -trimpath -tags desktop,production -ldflags "-s -w -H windowsgui -X main.appVersion=1.0.0 -X main.buildDate=ci" -o bin/ahtool_v1.0.0.exe .
```

注意：
- CI 需要 Go 1.26.x（`x/sys v0.48.0` 要求）。
- `rsrc.syso` 已提交；如果 CI 重新生成，需安装 `go-winres` 并执行上面的命令。
- 可复现性受 Go 版本、`-trimpath`、依赖版本锁定影响；本仓库 `go.sum` 已锁定依赖。
