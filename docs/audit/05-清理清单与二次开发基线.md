### 关键点

- Go 1.26+。依赖 `golang.org/x/sys v0.48.0` 要求 `go >= 1.26.0`；本机原先只有 1.22.8，已下载 Go 1.26.0 到 `toolchain126/`（未提交）。
- `GOARCH=amd64` 固定：启动项枚举依赖 64 位注册表视图，32 位会被 WOW64 重定向。
- `CGO_ENABLED=0`：Wails v2 的 Windows 后端可纯 Go 交叉编译；本次已产出 exe。
- `rsrc.syso` 重建命令（需 `go-winres`）：

```bash
go install github.com/tc-hib/go-winres@latest
go-winres simply --arch amd64 --out rsrc --no-suffix --manifest gui --admin \
  --icon app.ico --file-version 1.0.0.0 --product-version 1.0.0.0 \
  --file-description "ah系统优化工具箱" --product-name "ah系统优化工具箱 (ahtool)" \
  --original-filename "ahtool.exe" --copyright "GPLv3"
```

> `--no-suffix` 在部分版本仍生成 `rsrc_windows_amd64.syso`，需重命名为 `rsrc.syso`。

### 测试

```bash
go test ./...                # 安全测试集（纯逻辑/临时目录）
go test -tags manual ./...   # 真机测试：管理员、真实磁盘、注册表、服务
```

- 默认测试不扫真实磁盘；`manual` 测试可能写入 `%LOCALAPPDATA%\ahtool`、HKCU 测试键、服务状态，请在 VM 中运行。

## 四、如何新增一个工具

1. 在 `tools_<cat>.go` 的 `init()` 里加 `regTool(ToolItem{...}, toolImpl{...})`。
2. 必填 `ID/Cat/Name/Desc/Cmd/Risk/Timeout`；`Risk` 只能是 `safe/readonly/caution/reboot`。
3. 执行方式三选一（`Run > Plan > Steps`，不能混用）：
   - `Steps`：固定命令序列；
   - `Plan(arg)`：参数决定命令；
   - `Run(tc)`：要解析输出/多步交互。
4. 改系统的给 `Danger: true`；需重启给 `Reboot: true`；要备份给 `Backup: true`（目前只有 `fix-boot` 走 `backupBCD`）。
5. 跑 `go test -run 'TestTool|TestServiceGuides' .`；数量/分布变了同步 `toolkit_test.go`。
6. 刷新规格基线：`GOLDEN_UPDATE=1 go test -run TestToolGolden .`。

## 五、如何新增一项优化

1. `OptItem` 结构在 `optimize_data.go` 顶部：`ID/Name/CheckKey/CheckValue/Optimized/Optimize/Restore/...`。
2. 新项加到 `optimize_data.go` 或 `optimize_extra.go`；`Optimize` 是动作数组（`regwrite/regdelete/service/cmd/shellnotify`），`Restore` 必须写“回到原值”的动作。
3. **生成器缺失**：文件头写的 `_proto/gen_optimize_data.py` 不在仓库；当前只能手工维护。建议补生成器或移除“Code generated”声明。
4. 预设数量：Basic 87 / Deep 127；新增项要决定是否进入预设。
5. 安全项（UAC/SmartScreen/防火墙/内存完整性/VBS）不要放进 Deep 默认勾选。
