# 03 · 工具库机制与可用性核验

- 对象：`ahtool` v1.0.0 工具库（36 个工具，5 个分类）
- 日期：2026-11-12
- 方法：静态阅读 + 计数核对 + 交叉编译；**未在 Win11 真机逐个执行**（审计底线：不做真机删除/服务启停/注册表写入/驱动操作）。
- 结论：机制清晰、注册校验完善、执行链统一；风险标注与“可回滚”承诺**不完全一致**；约 6–8 个工具在 Win11 / 精简系统上存在可用性边角。

---

## 一、机制：工具怎么注册、怎么执行

### 1. 注册

- 一个工具 = `ToolItem` 元数据 + `toolImpl` 执行方式，在 `tools_*.go` 的 `init()` 里调用 `regTool(...)`（`toolkit.go:185`）。
- `registerTool`（`toolkit.go:136`）逐项校验：
  - ID 非空且不重复（`:143`）；
  - Name/Desc/Cmd 非空（`:140`）；
  - 分类必须在 `toolCats` 里（`:150`）；
  - `Risk` 只能是 `safe/readonly/caution/reboot`（`:153`）；
  - `ArgKind` 白名单（`:158`）；
  - 有参数必须有 `ArgLabel`（`:164`）；
  - `Timeout > 0`（`:170`）；
  - `Run/Plan/Steps` 三选一，不能混用（`:173-178`）。
- 填错直接 `panic`（`:187`），启动即暴露。
- 分类定序由 `buildCatalog`（`toolkit.go:125`）按 `toolCats` 顺序拼装，避免 `init()` 文件名字母序漂移。
- 基线：`toolkit_test.go:19` 钉死 36 个；`testdata/golden_tools.json` 是完整规格快照，`GOLDEN_UPDATE=1 go test -run TestToolGolden .` 刷新。

### 2. 执行分派

- `RunTool`（`toolkit.go:272`）：查定义 → 参数校验 → **互斥锁**（`:285-289`，同一时间只允许一个工具）→ `context.WithTimeout`（`:300-304`）→ 后台 goroutine 调 `execTool`。
- `execTool`（`toolkit.go:340`）：优先级 `Run > Plan > Steps`（`:364-371`）；`Backup` 为 true 时先 `backupBCD`，失败即中止（`:354-359`）。
- `runStepStream`（`toolkit.go:569`）：
  - `resolveExe` 解析 System32 绝对路径（`win_exec.go:68`）；
  - `HideWindow + CREATE_NO_WINDOW`（`toolkit.go:572`）；
  - 15 秒心跳、25 秒静默提示（`:597-616`）；
  - 输出经 `consoleReader`（UTF-16 检测，`:640`）→ `pumpLines`（`\r/\n` 切分、80ms 压帧，`:678`）→ `decodeConsole`（UTF-8/GBK，`win_exec.go:47`）。
- `StopTool` 只取消 context（`toolkit.go:263`），`exec.CommandContext` 会尝试结束子进程；孙进程是否被清理取决于 Windows 作业对象，当前未设置 Job Object（潜在残留）。
- 每个工具启动时写 `oplog.json`（`toolkit.go:290`），记录工具名与参数。

### 3. 备份与回滚的真实边界

- **只有 `fix-boot` 标了 `Backup: true`**（`tools_fix.go:72`），执行前 `bcdedit /export` 到 `%LOCALAPPDATA%\ahtool\reports`（`toolkit.go:756`）。
- `fix-restore-point` 是“创建还原点”，不是自动备份；用户不先跑它，改注册表/引导就没有回退点。
- `net-hosts` 会备份 hosts（`tools_net.go:461`）；`netHostsReset` 也备份（`:487`）。
- **其余 `Danger: true` 工具没有自动备份**：`fix-update`（`:101`）、`fix-update-remove`（`:117`）、`net-lanfix`（`:39`）。`net-lanfix` 会改服务启动类型、防火墙规则、网络配置文件，但没有导出/回滚。
- 结论：UI 上“带备份 / 可回滚”的承诺只对少数工具成立；二次开发应补齐或改文案。

### 4. “7 类”与“5 类”的口径

- 工具库代码里是 5 个 `toolCats`：`fix/net/disk/info/util`（`toolkit.go:96-102`）。
- README 原写的“7 类”是按**症状**分组的前端筛选（上不了网、更新装不上等），不是 `toolCats`。
- `optimize_data.go` 的 154 项是“系统优化”数据，不属于工具库；工具库是 36 个命令/操作。

## 三、风险标注与实际行为的偏差

| 工具 | 标注 | 实际 | 建议 |
|---|---|---|---|
| net-lanfix | caution/Danger | 改服务启动类型、防火墙规则、网络位置 | 增加执行前导出服务/防火墙状态；或改文案“不可自动回滚” |
| fix-update | caution/Danger | 重命名系统更新缓存目录 | 增加“已下载更新需重新下载”提示；失败时恢复原目录名 |
| fix-update-remove | reboot/Danger | 卸载补丁，可能影响系统稳定性 | 增加“先创建还原点”引导 |
| net-hosts | caution/Danger | 重置会覆写 hosts | 删除“重置为空”或二次确认 + 展示新内容 |
| disk-defrag-optimize | caution | 对 SSD 执行优化 | 检测媒体类型，SSD 只做 TRIM/不整理 |
| 所有 `Danger` | — | 大多无自动备份 | 统一“执行前备份/还原点”机制 |

## 四、可用性与编码方面的已知 bug / 边角

1. **`netNicRestart` 中文硬编码（已修）**：原 `tools_net.go` 只识别“已启用”，英文系统不可用；第二轮已改为兼容 `Enabled`，接口名取第 4 列起（`tools_net.go:548-559`）。
2. **`netTimeSync` 固定写三组时间服务器**（`tools_net.go:506`）：企业内网可能全部不可达；建议允许配置并显示实际使用的服务器。
3. **`fix-dism-restore` 依赖 Windows Update 网络**：离线/禁用更新的机器会失败；UI 已提示“需要联网”，可接受。
4. **`fix-boot` 的 `bootrec` 在正常系统下可能找不到**：`resolveExe` 找不到就回退裸名，最终报“找不到文件”；应明确提示“请从 WinRE 运行”。
5. **`util-activation` 依赖 `slmgr.vbs` + `cscript`**：LTSC/精简版可能缺失；失败原因应区分“不支持”与“未激活”。
6. **`StopTool` 不杀孙进程**：`exec.CommandContext` 只结束直接子进程；`dism`/`sfc` 一般无孙进程，但 `cmd /c` 类可能有。建议用 Job Object 绑定。
7. **输出编码**：`consoleReader` 先读 4096 字节判断 UTF-16；若命令首块很晚/很小，可能误判；已有心跳，但可考虑用 `chcp 65001` 或统一 `> file` 再读。
8. **`fix-sfc` 的 CBS.log 摘要**：只读尾部 32MB，日志轮转/超大时可能读不到本次记录；代码已“没痕迹就安静”，可接受。
9. **超时与取消**：`runStepStream` 在 ctx 取消后 `cmd.Wait` 可能等待管道关闭；`StopTool` 后 UI 需观察是否真正退出。
10. **工具库 CLI 自检**：`-cli` 只跑垃圾扫描，不逐个跑工具；工具可用性仍以静态/单测为主。
