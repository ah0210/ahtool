# 12 · 蓝屏/异常关机分析 + 网络洞察 + 应用卸载修复

- 日期：2026-11-12
- 版本：v1.0.0（未改版本号）

## 一、蓝屏分析增强

在原转储解析基础上新增：

- 异常关机 / 蓝屏 / WHEA 时间线（最近 30 天）：
  - Kernel-Power 41：异常关机；
  - BugCheck 1001：蓝屏，带 BugCheck 代码/参数；
  - EventLog 6008：上次关机是意外的；
  - WHEA-Logger 17/18/19/20/46/47：硬件错误。
- 转储配置检查：`CrashControl` 的启用状态、转储类型、DumpFile、MinidumpDir、AutoReboot、Overwrite、LogEvent、AlwaysKeepMemoryDump。
- 归因提示：结合 BugCheck 码/参数与事件类型给出“可能方向 + 建议”，不把 41 直接判成电源损坏。
- 前端在蓝屏页新增时间线卡片，可刷新；原转储列表与详情弹窗保持不变。

数据只读：不删日志、不改转储配置、不上传。

## 二、网络洞察独立页

新增导航「系统维护 → 网络洞察」，只读：

- 网卡全景：名称/类型/状态/速率/MAC/IPv4/IPv6/网关/DNS/DHCP 服务器；
- 路由与出口：默认路由、系统代理/PAC/WinHTTP/环境变量；
- 连接与进程：TCP/UDP 原始连接，PID、进程名、exe 路径（悬停），分类为对外/内网/本地/监听；
- 端口暴露面：监听地址为 `127.0.0.1` / `0.0.0.0` / `::` 时标注“仅本机/对外”；
- ARP 邻居：`arp -a` 被动表，不主动扫描；
- WiFi：SSID/BSSID/状态/信号/速率（`netsh wlan show interfaces`）；
- 连接视图：原始连接 / 按进程聚合；
- 已知拓扑：基于默认路由 + ARP 的原生 SVG（只画已知关系，不代表扫描结果）；
- 快照对比：保存本机网络快照，对比最近两份的新 ARP/新端口/DNS 变更/新对外连接；
- 共享与网络发现：`net share` + FDResPub/SSDPSRV/upnphost/LanmanServer/LanmanWorkstation 状态；
- 分段连通性：用户点击后检查网卡→网关→DNS→公网，并单独做一次 DNS 解析；
- 刷新/筛选（全部/对外/内网/监听）。

实现口径：

- 数据源为 `GetNetworkInfo`（WMI/注册表）+ `netstat -ano` + `tasklist` + `route print` + `arp -a` + `net share` + `sc query`；
- 只读、不上传、不主动扫描局域网；分段检查只在点击时执行；
- 连接表最多 800 行、展示最多 400 行，避免大机器卡顿；
- 进程路径需要管理员权限，读不到时显示 PID/“—”，不编造。

局限：

- 当前连接/端口用 netstat/tasklist 文本解析，后续可换成 IP Helper（GetExtendedTcpTable/GetExtendedUdpTable）提升性能与准确性；
- ARP 被动表不等于设备可信；`0.0.0.0` 监听不等于防火墙放行；拓扑只画已知关系；
- 链路质量趋势、完整设备指纹仍为后续 Phase。

## 三、应用卸载卡住修复

现象：卸载程序已退出，但列表项仍在，界面一直显示“卸载程序已退出，但列表里还在…”，最长等 8 分钟。

原因：

- 前端要求“卸载程序退出 + 列表项消失”才结束；
- 部分卸载器退出后不清自己的 Add/Remove Programs 注册表项，或需要重启才清；
- 原逻辑只能等到 8 分钟超时。

修复：

- 后端 `PollUninstall` 在进程退出 20 秒后仍未清注册表项时返回 `state=stale`；
- 前端收到 `stale` 立即停止等待，提示“卸载程序已退出，但系统列表项仍在（可能需重启或卸载器未清注册表）”，并转入残留清理；
- 不再干等 8 分钟，也不会把仍在运行的卸载程序误判完成（进程存活时仍按原逻辑等待）。
